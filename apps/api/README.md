# BSTU International API

Laravel 13 REST API for BSTU International public content, student portal, and apanel administration.

## Project API Conventions

- Public endpoints live under `/api/v1` and are implemented primarily by `Api\PublicApiController`.
- Student endpoints are protected by `auth:sanctum` and must always scope records to the authenticated student's profile.
- Apanel endpoints are protected by `auth:sanctum` plus `role:apanel`; generic CRUD access is limited to the whitelist inside `Api\AdminCrudController`.
- Successful JSON responses use `success`, `message`, and `data`; optional response metadata can be added as `meta`.
- Error JSON responses use `success`, `message`, and `errors`.
- Validation belongs in Form Request classes where practical; apanel dynamic CRUD validation is centralized in `AdminCrudController::getValidationRules`.
- User passwords must always be hashed before persistence. Do not bypass the controller/helper path for apanel user CRUD.
- Database changes should be additive migrations. Do not edit old migrations after they have run on a shared database.
- Seeders should be idempotent and keyed by stable slugs/codes/emails/locales. Avoid rerunning content seeders over admin-edited records without reviewing ownership.
- Public routes are rate limited by `public-api`; login/register/password reset have stricter dedicated limiters.
- Public CMS responses for locales, translations, settings, menus, home, pages, faculties, departments, and programs are cached with `PUBLIC_API_CACHE_TTL`.
- Apanel writes to public content resources rotate the `public_content_cache_version` key. Manual cache reset remains available through `cache:clear` and `optimize:clear`.
- Student document uploads accept only PDF/JPEG/PNG/WebP up to 10 MB. Apanel media uploads accept PDF/images/video up to 50 MB.

## Local Checks

```bash
.\php-local.bat artisan route:list
.\php-local.bat artisan migrate:status
.\php-local.bat artisan test
.\php-local.bat artisan optimize:clear
.\php-local.bat artisan cache:clear
composer validate
```

Do not run `migrate:fresh` against a real or shared database.

## Developer Readiness

Start the backend locally from `apps/api`:

```bash
.\serve-local.bat
```

Verify the local PHP runtime and required extensions:

```bash
.\php-local.bat -v
.\php-local.bat -m
.\php-local.bat --ini
```

Required extensions include `pdo_mysql`, `mysqli`, `openssl`, `mbstring`, `fileinfo`, `curl`, `tokenizer`, `xml`, `ctype`, and `json`. Enable `sodium` for hardened production token/crypto support when available.

Use normal additive migrations for shared databases:

```bash
.\php-local.bat artisan migrate
.\php-local.bat artisan migrate:status
```

Run targeted seeders only when the target records are system-owned:

```bash
.\php-local.bat artisan db:seed --class=LocaleSeeder
.\php-local.bat artisan db:seed --class=PermissionSeeder
.\php-local.bat artisan db:seed --class=RoleSeeder
```

Storage and cache commands:

```bash
.\php-local.bat artisan storage:link
.\php-local.bat artisan optimize:clear
.\php-local.bat artisan cache:clear
```

Production checklist:

- Set `APP_ENV=production` and `APP_DEBUG=false`.
- Narrow `CORS_ALLOWED_ORIGINS` and set `SANCTUM_STATEFUL_DOMAINS`.
- Set `SANCTUM_TOKEN_EXPIRATION_MINUTES`.
- Use production cache/queue/log drivers, preferably Redis or equivalent managed services.
- Confirm `public/storage` is linked and uploads are backed up.
- Run `composer validate`, `composer audit`, `npm.cmd audit --audit-level=high`, `pint --test`, `route:list`, `migrate:status`, and `artisan test`.

Troubleshooting:

- `could not find driver`: check `.\php-local.bat -m` and confirm `pdo_mysql` is enabled in `php.ini`.
- `public/storage NOT LINKED`: run `.\php-local.bat artisan storage:link`.
- CORS failures: check `CORS_ALLOWED_ORIGINS`, `CORS_SUPPORTS_CREDENTIALS`, and browser origin.
- Sanctum/token failures: confirm `Authorization: Bearer <token>`, token expiration, and `SANCTUM_STATEFUL_DOMAINS` for SPA cookie mode.
- Stale config/cache: run `.\php-local.bat artisan optimize:clear`.

## File Cleanup Classification

- `bootstrap/cache/packages.php` and `bootstrap/cache/services.php` are generated Laravel/Composer discovery cache files. They can be removed locally with `optimize:clear`; keep `bootstrap/cache/.gitignore`.
- `.phpunit.result.cache` is generated by PHPUnit and is ignored.
- `database/data/*.json` files are seed/import datasets. Most are consumed directly by seeders; `services.json` is retained as a legacy import output while `ServiceSeeder` uses curated inline service records.
- `public/storage` is a Laravel junction/symlink to `storage/app/public`. Do not delete it and do not treat files seen under both paths as duplicates.
- `node_modules/.package-lock.json` is npm's installed dependency metadata. Do not edit it manually.
- `package-lock.json` and `node_modules/.package-lock.json` using `lockfileVersion: 3` is normal for modern npm. Do not change it to `0`.
- The nested `apps/api/.github/workflows` files are Laravel skeleton workflow references. In this monorepo they are not the active repository-root workflows unless `apps/api` is split into its own GitHub repository.

- [Simple, fast routing engine](https://laravel.com/docs/routing).
