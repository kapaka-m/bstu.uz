- `apps/api/routes/api.php`
- `PublicApiController`
- `HomeCmsController`
- `AdminCrudController`

## نتيجة فحص الديناميكية وعدم وجود محتوى static

- الصفحات المذكورة تعرض محتوى التشغيل من API والجداول المرتبطة بها.
- الصفحة الرئيسية تستخدم `homeCmsService` و hook `useHomeSection` لأقسام Hero وRegistrar وStats وIdentity وCore Values وغيرها.
- أقسام الصفحة الرئيسية الأخرى مثل News وBlog وVideo وGreen Campus وAnnouncements وLeadership وInteractive Services تستخدم خدمات API الخاصة بها.
- Header Web يستخدم `/api/v1/menus/header` من جداول `menus`, `menu_items`, `menu_item_translations`.
- Footer Web يستخدم `/api/v1/footer-web` من جداول `web_footers`, `web_footer_translations`.
- Locales والترجمات العامة تستخدم `/api/v1/locales` و `/api/v1/translations` من جداول `locales`, `translation_keys`, `translation_values`.
- صفحات `/login` و `/forgot-password` لا تملك CMS مخصص، لكن النصوص الظاهرة فيها تأتي من قاموس الترجمات العام، وعمليات الدخول/استعادة كلمة المرور من API وجداول المستخدمين والتوكنات.
- لا يوجد اعتماد تشغيل على ملفات static data لهذه الصفحات كمصدر محتوى. الموجود داخل React هو بنية العرض ومفاتيح الترجمة وبعض fallback UI labels فقط، وليس بيانات محتوى الصفحات.

## قابلية إضافة لغات جديدة

النظام جاهز لاستقبال أي عدد من اللغات لأن أغلب جداول المحتوى تعتمد على جدول ترجمة منفصل يحتوي عمود `locale`.

عند إضافة لغة جديدة:

1. تضاف اللغة في جدول `locales` وتكون `is_active = true`.
2. يجب إضافة صفوف ترجمة للغة الجديدة في جداول الترجمة المرتبطة بالمحتوى المطلوب.
3. الـ API يقرأ اللغة من `locale` أو `Accept-Language` ويستخدم fallback عند الحاجة.
4. صفحات apanel الخاصة بالمحتوى تستخدم أكواد اللغات من النظام، لذلك يمكنها التعامل مع لغات إضافية بعد إضافتها وتوفير ترجماتها.
